# Anim Retarget — Android (v1.1.1-test)

Android-приложение для переноса анимаций между зариганными 3D-персонажами.
Сборка ориентирована на GLB/GLTF, FBX и BVH. Это тестовая версия.

## Скачать готовый APK

1. Перейдите в [GitHub Actions](https://github.com/RayZenGreallyzzz/AnimRetargetAndroid/actions/workflows/android-debug-apk.yml).
2. Откройте последний успешный запуск **Build Anim Retarget APK**.
3. В разделе **Artifacts** скачайте `AnimRetargetAndroid-debug-APK`.
4. Распакуйте артефакт и установите `app-debug.apk` на планшет.

Сборка запускается автоматически при изменении исходников или workflow.
Также можно использовать **Run workflow**. Первый запуск не гарантирует успешную
сборку: если возникнет ошибка, её журнал виден на странице Actions.

## Исходники

В репозитории хранится полноценный исходный проект v1.1.1-test в виде файла
`payload/AnimRetargetAndroid_sources.b64` (base64 от tar.bz2).
GitHub Actions автоматически восстанавливает каталог `AnimRetargetAndroid/`
из этого пакета и собирает приложение с Gradle 8.6 / Android SDK 34 / JDK 17.

Для восстановления вручную:

```bash
base64 -d payload/AnimRetargetAndroid_sources.b64 | tar -xj
```

Пакет содержит Kotlin-файлы, AndroidManifest, ресурсы и конфигурации Gradle.
Исходники не зависят от недоступного zip-файла из чата.

## Известные ограничения

- Это тестовая сборка; качество переноса движений и APK ещё нужно проверить на устройстве.
- Предпросмотр пока рисует скелет, а не скинованный 3D-персонаж.
- Ретаргетинг нескольких клипов не означает их объединение в **один** GLB:
  исходная реализация экспортирует отдельный файл для каждого выбранного клипа.
- Для тестов рекомендуются небольшой GLB-персонаж и одна анимация Mixamo,
  прежде чем загружать ZIP с сотнями файлов.

## 1.1.2-test: исправление BVH-анимаций (25 октября 2026)

В видео с `Walking_01_01.fbx` обнаружена сильно деформированная вторичная анимация `Walking_01_01.retargeted` (22,92 с, 2752 кадров при 120 FPS); исходный клип Mixamo (0,97 с) остаётся нормальным. Исправления в `hotfix/retarget_math_hotfix.py` применяются автоматически при APK-сборке:

- `Q.fromMat()`: исправлена инверсия поворота при матрица→кватернион (тест 28 ориентаций: 4 оси × 7 углов);
- `Pipeline.kt`: устранены скачки экспортируемых FBX Euler-каналов на границе ±180°.

Kotlin-ядро с изменениями компилируется. Полноценная визуальная правильность конкретного BVH требует повторной проверки после установки нового APK; неизвестно, насколько хорошо сопоставляются кости и исходные позы BVH. Размер FBX около 30 МБ сам по себе не означает ошибку.
